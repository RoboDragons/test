# レッスン 3: GitHubの機能活用

## 🎯 目標

Pull Request・Issue・コードレビューを使ったチーム開発の流れを習得します。

---

## 1. Issue（課題管理）

Issueはバグ報告・機能提案・タスク管理に使います。

### Issueの作成

1. リポジトリの **Issues** タブを開く
2. **New issue** をクリック
3. タイトルと説明を入力
4. ラベル・アサイン・マイルストーンを設定
5. **Submit new issue** をクリック

### 良いIssueの書き方

```markdown
## 概要
ログイン時にエラーが発生する

## 再現手順
1. ログインページを開く
2. 正しいパスワードを入力してログインボタンを押す
3. エラーメッセージが表示される

## 期待する動作
ログインに成功してダッシュボードが表示される

## 環境
- OS: Ubuntu 22.04
- ブラウザ: Chrome 120
```

### IssueをコミットやPRにリンクする

コミットメッセージやPRの説明に以下を書くと、Issue を自動でクローズできます：

```
Fix #42
Close #42
Resolve #42
```

---

## 2. Pull Request (PR)

PRは「このブランチの変更をマージしてください」というリクエストです。

### PRの作成手順

1. 作業ブランチをGitHubにプッシュ
   ```bash
   git push origin feature/my-feature
   ```
2. GitHubのリポジトリページで **Compare & pull request** をクリック
3. タイトルと説明を入力
4. レビュアーを指定（Reviewers）
5. **Create pull request** をクリック

### 良いPRの説明文

```markdown
## 変更内容
ユーザーのログイン機能を追加しました。

## 関連Issue
Close #42

## 変更点
- `src/auth.cpp` にログイン処理を追加
- `include/auth.h` にインターフェースを定義

## テスト
- [ ] ログイン成功のテストを追加した
- [ ] ログイン失敗のテストを追加した
```

---

## 3. コードレビュー

### レビューする側

1. PRの **Files changed** タブで差分を確認
2. コメントしたい行の `+` をクリック
3. コメントを入力して **Start a review** をクリック
4. すべて確認したら **Submit review** でフィードバックを送信

### レビューを受ける側

1. コメントに返信するか、修正する
2. 修正したらコミット・プッシュする（PRに自動で反映される）
3. 解決したコメントは **Resolve conversation** でクローズ

---

## 4. ラベル・マイルストーン

```
ラベル例:
  bug        - バグ
  enhancement - 機能改善
  documentation - ドキュメント
  good first issue - 初心者向け

マイルストーン例:
  v1.0.0 リリース
  春季大会対応
```
